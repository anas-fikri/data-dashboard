Alur Data Dashboard

Dari email perusahaan sampai dashboard yang dibagikan: bagaimana pengguna bekerja, apa yang terjadi pada file di belakang layar, dan komponen yang menjalankannya. Disarikan dari dokumen acuan docs/flow-kerja.md, keadaan 18 Oktober 2026.

Pengguna

Gambaran besar

Satu putaran kerja pemilik data, dari daftar akun sampai rekan memakai dashboard. Data baru cukup diunggah ulang ke dataset yang sama; dashboard tetap jalan.

Di belakang layar

Unggah dan proses file

File 1 GB tidak pernah dimuat utuh di browser atau di memori server. Browser mengirim potongan langsung ke penyimpanan; worker membacanya secara streaming dan menulis Parquet per sheet.

  • Diukur di produksi 18 Oktober 2026: CSV 100 MB siap ± 1 menit, 500 MB ± 5 menit; Excel 100 MB ± 2,5 menit, 500 MB dua sheet ± 8,5 menit.
  • Pekerjaan bisa diulang dengan aman: worker yang mati di tengah proses mengulang dari awal tanpa meninggalkan file setengah jadi.
  • Memilih ulang baris judul atau mengubah tipe kolom cukup membaca ulang raw.parquet, tanpa mengunggah file lagi.

Pengguna

Pakai dashboard

Widget tidak pernah mengirim SQL bebas. Aplikasi menerima spesifikasi widget yang tersimpan plus filter yang diizinkan, mengecek hak akses, lalu menjalankan query hanya pada kolom yang dibutuhkan.

  • Pada data 1 GB, 95 persen query widget selesai di bawah 261 milidetik; hasil yang sama berikutnya diambil dari cache.
  • Filter aktif tersimpan di alamat halaman, jadi tampilan terfilter bisa dibagikan sebagai tautan.

Pemilik data

Perbarui data

Pengganti "buka file Excel, tempel data baru, perbaiki formula yang rusak". Setiap unggahan menjadi versi baru yang berdiri sendiri; versi lama tetap tampil sampai versi baru siap.

Sistem

Status versi data

Satu dataset hanya punya satu versi yang sedang diproses pada satu waktu. Tiga versi SIAP terakhir disimpan; yang lebih lama dibersihkan otomatis.

Infrastruktur

Komponen di server olympus

Delapan layanan Docker Compose di satu VM. Hanya proxy yang membuka port ke jaringan; renderer PDF tidak bisa menjangkau penyimpanan, Redis, atau database.
