# T-011 — Perf widget tabel (CSV 1 juta baris)

- **Tanggal:** 2026-10-12
- **Mesin:** Apple M4 (10 core), RAM 16 GB, SSD lokal; Node 26; DuckDB 1.5.6. Mesin query: `memory_limit` 1 GB, `threads` 2, 2 query per user, sandbox sama dengan produksi. Dev server, worker, dan browser uji ikut berjalan (load average ± 12 saat diukur).
- **Fixture:** `npx tsx scripts/make-fixture.ts --kind csv --out tests/fixtures/perf/1jt-baris.csv --rows 1000000 --cols 10 --text-ratio 0.3 --unique-ratio 0.2 --number-locale id --delimiter ";"` — 120 MB, dihapus setelah diukur.
- **Perintah:** `npx tsx --conditions=react-server scripts/perf-widget-table.ts tests/fixtures/perf/1jt-baris.csv`.
  - Ingest sungguhan (raw + typed), lalu widget tabel 6 kolom pertama lewat `runWidgetQuery` (spec diambil dari widget, sama dengan `/api/query { widgetId, page, sort }`).
  - **Tanpa cache hasil** — setiap permintaan dijalankan DuckDB; cache parquet lokal sungguhan.
  - 8 skenario × 5 permintaan: tanpa urutan; urut angka menurun di halaman 1, 2, tengah (5.000), terakhir (10.000); urut teks menaik di halaman 1 dan tengah; urut tanggal menurun di halaman 1.
  - Tiap permintaan = `count(*)` dengan filter + halaman 100 baris (`ORDER BY kolom, _row LIMIT 100 OFFSET n`) dalam satu slot.

## Hasil

| Ukuran | Nilai |
|---|---|
| Ingest CSV 1 juta baris (raw + typed) | 9,2 s |
| Semua permintaan (40×) | p50 **33 ms**, p95 **114 ms**, maks **115 ms** |
| Tanpa urutan, halaman 1 | p50 10 ms |
| Urut Ongkir (desimal) menurun, halaman 1 / 2 | p50 33 ms |
| Urut Ongkir menurun, halaman tengah / terakhir | p50 104 ms / 114 ms |
| Urut No Resi (teks) menaik, halaman 1 / tengah | p50 33 ms / 51 ms |
| Urut Tanggal Kirim menurun, halaman 1 | p50 33 ms |
| Puncak RSS proses (ingest + query) | 416 MB |

Setiap halaman berisi tepat 100 baris; total 1.000.000.

## Lolos/tidak terhadap AC

- **AC 5** (widget tabel atas sheet 1 juta baris, sort + pindah halaman, respons < 2 detik): **lolos** — maks 115 ms tanpa cache hasil, termasuk halaman terakhir (OFFSET 999.900).

## Catatan

- Halaman makin jauh makin mahal (top-N DuckDB harus mempertahankan OFFSET + 100 baris), tetapi bahkan halaman terakhir 1 juta baris tetap ~0,1 s.
- Di aplikasi, permintaan halaman/urutan yang sama dilayani cache hasil (kunci = spec widget + urutan + halaman + revisi skema).
- Uji beban banyak user bersamaan ada di T-024.
