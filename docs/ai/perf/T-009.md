# T-009 — Perf API query deklaratif (CSV 10 juta baris)

- **Tanggal:** 2026-10-12
- **Mesin:** Apple M4 (10 core), RAM 16 GB, SSD lokal; Node 26; DuckDB 1.5.6. Mesin query: `memory_limit` 1 GB, `threads` 2, sandbox (enable_external_access=false, allowed_directories, lock_configuration).
- **Fixture:** `npx tsx scripts/make-fixture.ts --kind csv --out tests/fixtures/perf/10jt-baris.csv --rows 10000000 --cols 6 --text-ratio 0.3 --unique-ratio 0.2 --number-locale id --delimiter ";"`. Hasilnya 854 MB, dan dihapus setelah diukur.
  - Dipakai 6 kolom, bukan 10, karena disk mesin uji tersisa ± 3,4 GB.
- **Perintah:** `npx tsx --conditions=react-server scripts/perf-query.ts tests/fixtures/perf/10jt-baris.csv`.
  - Skrip menjalankan ingest sungguhan (raw + typed), lalu 20× `runQuery`, dengan mesin DuckDB dan cache parquet lokal sungguhan.
  - Repo/DB dan Redis dipalsukan in-memory.
- **Spec:** dimensi `Keterangan 2` (teks) + `Tanggal Kirim` per bulan; ukuran `sum(Ongkir)` + `count(*)`; limit 10.000.
  - Hasil 10.000 baris (limit tercapai), jadi query ini group-by dengan banyak grup.

## Hasil

Diukur ulang setelah review keamanan putaran 2–3. Perubahannya: unduhan di luar slot query, perkiraan byte hasil = perkiraan heap (rowBytes), entri cache hasil ≤ 4 MiB. Dev server dan worker ikut berjalan di mesin yang sama (load average ± 3–4).

| Ukuran | Nilai |
|---|---|
| Ingest CSV 10 juta baris (raw + typed) | 57,4 s |
| Query tanpa cache hasil (mesin DuckDB), 20× | p50 **572 ms**, p95 **608 ms**, maks 652 ms (pertama, termasuk salin parquet ke cache lokal) |
| Query dengan cache hasil, 20× | p50 0 ms, p95 0 ms; pertama 573 ms (miss) |
| Puncak RSS proses (ingest + query) | 938 MB |

Pengukuran pertama (sebelum review putaran 2, mesin lebih senggang) mencatat tanpa cache p95 424 ms dan dengan cache p95 2 ms.

Saat batas entri cache masih 1 MB, cache hasil tidak terpakai sama sekali untuk spec ini (p50 564 ms). Penyebabnya: hasil 10 ribu baris ≈ 2,2 MB menurut perkiraan heap yang baru. Karena itu batas entri dinaikkan ke 4 MiB.

## Lolos/tidak terhadap AC

- **AC 6** (CSV 10 juta baris, group-by 2 dimensi + 2 ukuran 20× beruntun, p95 < 3 detik): **lolos**.
  - Tanpa cache hasil p95 608 ms; dengan cache p95 0 ms.
  - Angka tanpa cache yang dijadikan acuan, karena spec yang sama 20× akan dilayani cache setelah permintaan pertama.

## Catatan

- File typed.parquet disalin sekali ke cache lokal (LRU, `MAX_LOCAL_PARQUET_BYTES`). Query berikutnya membaca dari disk lokal dengan proyeksi kolom dan statistik row group Parquet.
- Batas waktu 30 s dan slot (4 global, 4 per user) tidak tersentuh di uji ini. Uji beban bersamaan banyak user ada di T-024.
